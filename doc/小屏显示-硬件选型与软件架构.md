# TokenMonitor 小屏显示：硬件选型与软件架构方案

> 状态：方案设计（未落地代码改动）· 2026-11-15 · 证据分级见文末

## 一、一句话结论

TokenMonitor 本身就是 PC 上位机，**不需要另写独立程序**。按硬件分 5 条路，**主线推荐「方案 A：图灵智显 3.5 寸」（已开发 80%，最省事）**；日后想要实时动画 / 会话状态，再升级到「方案 B：ESP32 独立屏」。

## 二、选型决策树

```
你要什么体验？
├─ 完整悬浮窗画面 ──────────────────► 方案 E · HDMI/Type-C 便携屏（零代码）
└─ 数据 / 状态即可
    ├─ 要实时动画（30-60fps）──────► 方案 B · ESP32 独立屏（刷现成固件）
    └─ 低频即可（几秒刷新）
        ├─ 3.5 寸小屏 ────────────► 方案 A · 图灵智显 3.5（已开发）
        └─ 大屏多内容 ────────────► 方案 C · TURZX 5.2/8.8/9.2 寸
```

（方案 D · Thermalright Trofeo Vision 仅 macOS，平台不符，见附录）

## 三、共同架构（吸取别人经验后统一）

所有方案都是同一模式：**PC 上位机（TokenMonitor）+ 屏侧渲染**。TokenMonitor 持有数据，天生就是上位机。

```
TokenMonitor（PC，上位机，持有 token 数据）
   │
   ├─ A: 渲染整帧 RGB565 ─► USB CDC 串口 ─► 图灵 3.5"（CH552T 自绘）
   ├─ B: 导出简化 JSON ─► HTTP/串口 ─► ESP32（固件自绘，实时）
   ├─ C: 导出数据 ─► TURZX 大屏（官方软件 / 第三方）
   ├─ D: 导出数据 ─► Trofeo 6.86"（HID，JPEG，macOS）
   └─ E: 系统级副屏 ─► HDMI/Type-C 便携屏（原样画面）
```

## 四、五个方案详解

### 方案 A · 图灵智显 3.5 寸（主线，已开发 80%）

| 项 | 内容 |
|---|---|
| 硬件 | TURZX 3.5" IPS，480×320，USB Type-C，CH552T（16KB Flash / 1KB RAM，无帧缓冲），约 ¥60–100 |
| 连接 | USB CDC 虚拟串口（免驱，设备管理器出现 COM 口，非显示器） |
| 刷新 | 1.5–2 秒/帧 ≈ 0.5fps，状态变化触发，非实时 |
| 软件 | `render_screen.py` 渲染整帧 → RGB565 → `send_to_screen.py` 分块（2560B×120）串口下发 |
| 已完成 | 渲染、协议自检、RGB565 往返、横竖屏 UI 三版迭代 |
| 待办 | 屏到手 L1 点亮验证；TokenMonitor → JSON 定时导出自动化 |
| 优 | 便宜、免驱、USB 直连、零硬件改造、已开发大半 |
| 劣 | 无帧缓冲、不能实时、同名不同物坑（Revision A/B 协议互不相容） |
| 适合 | 余光扫一眼今日 token 用量 + 状态，低频 |

### 方案 B · ESP32 独立屏（主流，可实时）

| 项 | 内容 |
|---|---|
| 硬件 | Cheap Yellow Display 3.5"（ESP32-3248S035，480×320）约 ¥100–150；或 LILYGO T-Display-S3 1.9"、Waveshare ESP32-S3-LCD-1.47、ESP32-S3 Box 3 |
| 连接 | WiFi（LAN）+ USB 供电 / 刷机；或 USB 串口 |
| 刷新 | 实时 30–60fps，可做动画、会话状态机 |
| 软件 | `bridge.py`（Python stdlib，读 SQLite → 简化 JSON）→ HTTP `:8787` → ESP32 固件自绘 |
| 现成复用 | `rafelton/claude-usage-view-esp32`（零依赖 bridge + captive portal 配 WiFi + 3 板尺寸一套代码 + 断链保留上一帧/状态横幅）；`flexmox/ClaudeGauge`（功能最全 + WYSIWYG 设计器）；`sammcj/espclaude`（burn rate + 限额预测） |
| 工作量 | 中——改 bridge 数据源（Claude OAuth → TokenMonitor SQLite / SumStats），固件基本不动 |
| 优 | 实时、生态最丰富、状态机（正在跑/等你/完成）、断链韧性好 |
| 劣 | 要买板、刷固件、配 WiFi，比图灵复杂 |
| 适合 | 想要实时跳动、会话状态、burn rate 的体验 |

### 方案 C · TURZX 大屏（内容最多）

| 项 | 内容 |
|---|---|
| 硬件 | TURZX 5.2"（960×320）/ 8.8"（1920×480）/ 9.2"（1920×462），带 SD 卡可本地播放视频 |
| 连接 | USB Type-C |
| 刷新 | 中低频（分辨率高，整帧更大） |
| 软件 | 官方 UsbMonitor.exe（皮肤+天气，无 token）；或 `nuitsjp/token-dashboard`（Go，Hub 模式）；或 `mathoudebine/turing-smart-screen-python` 主题 + CustomDataSource |
| 工作量 | 中；`token-dashboard` 为第三方聚合站信息，未核到一手仓库，需先验证 |
| 优 | 分辨率高、内容多、官方软件兜底 |
| 劣 | 贵、占空间、第三方方案证据弱 |
| 适合 | 大屏同显额度 / 趋势 / 多 provider |

### 方案 D · Thermalright Trofeo Vision（不推荐）

- 硬件：6.86" 1280×480，USB-C，HID（VID:PID 0416:5302）
- 软件：`christensen143/claude-trofeo-hud`（Python + uv，2fps JPEG 推流）
- **macOS 专属，与用户 Windows 平台不符**；2fps 也非实时。仅记录，不推荐。

### 方案 E · HDMI/Type-C 便携屏（唯一能显示完整画面）

| 项 | 内容 |
|---|---|
| 硬件 | 任意 HDMI/Type-C 便携屏，1080p / 2K，约 ¥300–500 |
| 软件 | 零代码——Windows 扩展桌面，悬浮窗拖过去 |
| 刷新 | 真实 60fps，完整画面（含圆球动画） |
| 优 | 零开发、原样画面 |
| 劣 | 占桌面、费显卡（悬浮窗小，影响小）、贵、非专用小屏质感 |
| 适合 | 就要完整悬浮窗画面时（此前已明确要数据而非画面） |

## 六、从别人经验吸取的 6 条设计经验（任何方案实现都要遵循）

1. **断链 / 数据 stale → 保留上一帧 + 状态横幅**，不伪装实时（rafelton）
2. **数字变短防残影 → 固定宽度格式化**（turing-smart-screen-python）
3. **WiFi 凭据用 captive portal 配**，不硬编码（rafelton）
4. **stale 检测**：POLL_INTERVAL + STALE_DATA_SECONDS（espclaude）
5. **架构统一为 PC bridge + 屏自绘**，TokenMonitor 即上位机
6. **空态 / 错误态可区分**（本项目质量门禁）

## 九、失效触发条件

- 换屏型号 / 主控 → 方案 A 的协议与字节序结论失效
- 改用 ESP32 / TURZX → 直接抄现成项目，不用自己造
- TokenMonitor 表结构变更 → render / bridge 数据源需同步
